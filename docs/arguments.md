# Training settings

Start with the YAML generated by `ftgspp prepare dataset`. Most captures need
only the correct paths, FPS and camera split before a first run.

## Inspect the effective settings

```bash
ftgspp train --config /path/to/capture/ftgspp.yaml --print-config
```

This resolves the training budget without starting training or downloading
models. For user point clouds it reads the selected PLYs to count points.
It does not check image quality or whether the model fits your GPU.
The actual run saves its settings in `RUN/config.resolved.yaml`.

## Choose a budget

| `train.preset` | Use it for |
|---|---|
| `preview` | A shorter run to check inputs and the training path |
| `balanced` (default) | Your first quality-oriented run |
| `extended` | More training when held-out quality is still improving |

```bash
ftgspp train --config /path/to/capture/ftgspp.yaml \
  --output runs/preview --set train.preset=preview
```

Presets adapt optimizer steps to the number of frames. They keep the same
resolution, initialization and model size. **Preview reduces time, not peak
model memory.** These budgets are starting heuristics, not quality guarantees.

Foreground balanced uses 70,000 main steps at 121 frames and 174,000 at 300.
Preview uses half that budget; extended uses 1.5 times it. Explicit values such
as `train.iterations: 90000` override the preset. Remove a copied iteration
count, or set it to `null`, to restore adaptation.

## Scene adaptation

Choose the mode when [indexing your images](first-run.md):

| Default | Foreground | Scene |
|---|---|---|
| Target | Masked subject | Whole RGB image |
| Image scale | `1.0` | `0.5` |
| Initialization | Prepared carving | Existing RGB points, otherwise DA3 |
| Keyframe spacing | Every frame | Roughly 1/6 second |
| Color correction | Off | On |
| Hard separation (HS) | Off | On |

Scene balanced uses 30,000 main + 3,000 HS steps at 60 frames, or 150,000 +
15,000 at 300 frames. `train.iterations` counts main steps only.
HS starts from the selected main model and exports its terminal model;
`ckpt/main_selected.npz` keeps the pre-HS model for comparison.

Automatic scene spacing is stride 10 at 60 FPS, 5 at 30 FPS, or 4 at 24 FPS,
clamped for short clips. Use a smaller stride for fast motion. Existing clouds
need their actual stride; supply it when indexing with `--keyframe-stride N`.

## Settings worth changing

| Setting | When to change it |
|---|---|
| `data.fps` | Always match the indexed capture rate |
| `data.frames.start`, `.stop` | Select a shorter clip; stop is exclusive |
| `data.train_cameras`, `.eval_cameras` | Reserve views for checking novel-view quality |
| `data.scale` | Lower it for image-buffer memory pressure; `0.5` halves each image dimension |
| `init.num_gaussians` | Lower for model/optimizer memory pressure; increase for more capacity |
| `init.keyframe_stride` | Reduce for fast motion; larger values prepare fewer clouds |
| `init.duration` | Usually leave `null`: temporal support follows stride and FPS |
| `train.iterations` | Set an explicit main-phase budget instead of a preset |
| `train.save_checkpoints` | Disable to save disk if optimizer resume is unnecessary |

Changing scale, frames, calibration or camera split requires matching prepared
geometry. Changing stride requires matching keyframe clouds. Use a new output
directory for each experiment. Check masks and geometry before increasing steps.

## `max_points`: per keyframe versus the total model

| Setting | What it controls |
|---|---|
| `init.num_gaussians` | Total model size: generated geometry defaults to 2M; user `points` defaults to the selected PLY population |
| `init.da3.max_points` | Dense reference points **per keyframe**; `null` adapts automatically |
| `prepare points --max-points N` | Explicit cap per prepared keyframe |
| `prepare points --quality fast\|balanced\|high\|full` | Generated candidate density; default `balanced`, `full` removes the automatic cap |
| `prepare points --resolution N` | Carving grid resolution along each axis; default `128` |

The total model budget is shared across the clip. Longer clips may need more
capacity or shorter segments; more iterations cannot replace missing capacity.
Carving uses calibrated mask bounds when possible and falls back to DA3 when
needed. Use `--bounds-method da3` to request DA3 bounds explicitly.

## Paths and overrides

YAML paths resolve relative to the YAML file; CLI paths, including `--set`,
resolve relative to your working directory. For environment variables in YAML,
use `${oc.env:VARIABLE}` rather than a literal `$VARIABLE`.
Unknown config keys are rejected.

```bash
ftgspp train --config /path/to/capture/ftgspp.yaml \
  --output runs/longer --set train.iterations=90000
ftgspp train --resume runs/longer --print-config
```

Resume keeps the saved plan and rejects new-run overrides. To tune a model,
start a separate experiment with the same held-out cameras.

## Batch size

Keep the default B1 initially. `train.batch_size: 4` supports single-device
foreground with color correction and HS disabled, `distributed.mode: off`,
`distributed.sampling_policy: flat_epoch`, and no automatic LR scaling.
Iterations count optimizer updates, so the same count at B4 sees four times as
many images. See [benchmarks](performance.md#local-batch-execution-cost) before
comparing throughput or budgets.
